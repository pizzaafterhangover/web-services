## 세부 구조도

<RosGraph

  width={800}
  height={545}
/>

- 대표 노드 perception_master는 영상을 주고받는 컴포넌트를 한 프로세스에 묶는 컨테이너이자, 다른 파트로 나가는 출구다. 카메라 드라이버를 컨테이너 안에 두는 것은 권장이며 아직 정하지 않았다.
- 선반 평면 투영은 detector 안에서 한다. puck_map은 투영된 /perception/pucks와 TF로 퍽 지도를 만든다.
- AprilTag·바코드는 입력 카메라, 용도, 출력 토픽이 모두 미정이다.

## 노드 목록

대표 노드는 ★로 표시했다. 전체 페이지의 노드 목록에서 이 파트만 옮겼다.

| 노드 | 하는 일 | 구분 |
| --- | --- | --- |
| ★ perception_master | 파트 출구이자 컴포넌트 컨테이너 | 직접 작성 |
| realsense2_camera (전면, 그리퍼) | 전면 D435: 컬러, 정렬된 depth, 점구름(640×480, 15-30 fps, align_depth.enable:=true). 그리퍼: 손 카메라 영상. 컨테이너 안 컴포넌트로 두는 것을 권장(미정) | 기존 패키지 |
| detector | YOLO 모델 하나로 두 카메라 처리. 프레임별 검출, 선반 평면 투영 → `/perception/pucks`. 경광등도 같은 모델로 검출 | 직접 작성 |
| puck_map | `/perception/pucks`와 TF로 퍽 지도 → `/perception/puck_map`, set_state 서비스 | 직접 작성 |
| tower_light | detector 결과로 경광등 판단 → `/perception/tower_light` | 직접 작성 |
| hand_align | 그리퍼 카메라로 집기 직전 정렬 → `/perception/hand_target` | 직접 작성 |
| apriltag_detector, barcode_reader | AprilTag 검출, 바코드 읽기. 입력 카메라·용도·출력 토픽 미정 | 미정 |
| localization | 위치 추정. (가) visual_slam / (나) robot_localization EKF + map → odom(출발 자세 고정값, 필요하면 AMCL) | 미정 |

## 커스텀 메시지 (team_interfaces)

이 파트가 보내거나 받는 메시지만 옮겼다.

<Callout type="warn" title="초안">
  아직 회의 중인 초안이다. msg 파일이 바뀌면 모든 팀원이 team_interfaces를 다시 빌드해야 한다.
</Callout>

**PuckMap.msg**

```text
std_msgs/Header header         # frame_id: map, stamp: 마지막 갱신 시각
MappedPuck[] pucks
```

**MappedPuck.msg**

```text
uint32 id                      # 고유 번호, 임무 내내 유지
uint8 COLOR_RED=0
uint8 COLOR_GREEN=1
uint8 COLOR_BLUE=2
uint8 color                    # 투표 결과
uint8 SHAPE_CYLINDER=0
uint8 SHAPE_BOX=1
uint8 shape                    # 투표 결과
bool standing                  # 투표 결과
geometry_msgs/Point position   # map 기준 m, 가중 평균 (z≈0.08)
float32 yaw                    # 그리퍼 롤 목표각 (rad)
float32 position_std           # 위치 불확실도 (m)
uint16 n_obs                   # 관측 횟수
builtin_interfaces/Time last_seen
uint8 STATE_TENTATIVE=0        # 관측 부족
uint8 STATE_CONFIRMED=1
uint8 STATE_PICKED=2
uint8 STATE_LOST=3             # 집기 실패 등으로 사라짐
uint8 state
```

**SetPuckState.srv**

```text
uint32 id
uint8 state                    # MappedPuck의 STATE_*
---
bool success
string message
```

**TowerLight.msg**

```text
std_msgs/Header header
bool detected                  # 경광등이 보이는지
```

## 통신 규칙

| 토픽 | 발행 주기 | 결과가 없을 때 | QoS |
| --- | --- | --- | --- |
| 카메라 영상 | 약 15-30 Hz | | SensorData (best effort) |
| `/perception/puck_map` | 목록이 바뀔 때 + 주기적(약 1 Hz) | 빈 배열 | reliable, depth 1, transient local |
| `/perception/tower_light` | 프레임마다, 최근 N프레임 기준 | `detected: false` | reliable, depth 1, transient local |
| `/perception/hand_target` | 프레임마다 | `detected: false` | reliable, depth 1 |

- 받는 쪽이 '안 보임'과 '노드 고장'을 구분할 수 있도록, 인지 토픽은 결과가 없어도 항상 발행한다.
- **odom → base_link**: localization(인지) 하나만 낸다.
- **map → odom**: (나) 안이면 출발 자세 고정값 또는 AMCL, (가) 안이면 미정.
- 퍽 지도와 신호등 위치는 map 기준, 실시간 검출(`/perception/pucks`)은 base_link 기준.
- TF는 최신 값이 아니라 영상의 `header.stamp` 시각으로 조회한다.
- 카메라 기울기는 파라미터가 아니라 URDF(camera_link의 pitch) 한 곳에만 둔다.

인지가 줄여서 보내고, 팔 제어는 받은 값을 바로 롤 각도로 쓴다.

| 퍽 상태 | 대칭 | 보낼 범위 |
| --- | --- | --- |
| 서 있는 원통 | 어느 방향이든 같음 | 0 고정 |
| 서 있는 직육면체 | 90°마다 | −45°에서 +45° |
| 누운 원통 · 직육면체 | 180°마다 | −90°에서 +90° |

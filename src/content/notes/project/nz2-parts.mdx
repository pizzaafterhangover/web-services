## 개요

KANT PA1 LV2 프로젝트2 **팀NZ2**의 로봇은 RGB 퍽을 선반에서 선반으로 옮기는 모바일 매니퓰레이터다.
임무는 주어진 미로 지도 안에서 한 바퀴 돌며 퍽 위치를 파악한 뒤, 퍽을 색깔별로 옮기는 것이다(**규칙 확정 전 가정**).

이 페이지는 인지·판단·제어 파트가 주고받는 통신 규약이다. 파트 사이의 약속은 `/perception/...` 토픽과
`team_interfaces` 메시지 등 정해진 인터페이스로만 정하고, 각 파트 안쪽 구조는 바뀌어도 다른 파트에 영향이 없게 한다.

### 기준 사양

| 항목 | 값 |
| --- | --- |
| 차체 | 400 × 400 mm, 윗면 높이 180 mm, 스월브 4모듈 |
| 팔 | OpenMANIPULATOR-X, 링크 약 +100 mm 연장, 그리퍼 롤 회전 가능. 장착 위치 **[미정]** (상면 중앙 / 중심에서 40 mm 앞, 실물 확인 후 확정) |
| 카메라 | RealSense 2대. 차체 전면 D435(높이 약 180 mm, 기울기 미정, 일단 10°로 테스트), 그리퍼 1대. UC-684는 사용 여부 미정 |
| 그리퍼 거리 센서 | 집기 직전 거리 확인. 연결(OpenCR / Jetson) 미정 |
| 연산 | Jetson Orin Nano Developer Kit. L4T R39.2.1, Ubuntu 24.04.5 LTS, ROS 2 Lyrical (아래 "개발 환경 (Jetson)") |

## 계층과 원칙

노드를 5개 계층으로 나눈다. 위는 느리고 추상적으로 무엇을 할지 정하고, 아래로 갈수록 빠르고 구체적으로 실행한다.
구조는 컵 가져오기 로봇 7계층 설계를 참고했고, VLM과 강화학습 계층은 우리 임무에 필요 없어 뺐다.

| 계층 | 역할 | 대표 노드 | 주기 | 담당 |
| --- | --- | --- | --- | --- |
| ① 임무 관리 | 순회 → 운반 단계 진행, 대상 퍽과 순서, 재시도·건너뛰기, `/state/*` 발행, 장애 판정 | planning_master, health_monitor | 이벤트마다 | 판단 |
| ② 센서 · 인지 | 카메라, YOLO, 경광등·퍽 인식, 퍽 지도, 집기 정렬, AprilTag·바코드 | realsense2_camera ×2, perception_master(detector, puck_map, tower_light, hand_align, apriltag_detector, barcode_reader) | 15-30 Hz (퍽 지도 약 1 Hz) | 인지 |
| ③ 확정 실행 | 위치 추정, 경로 계획·추종, 팔 동작 순서 | localization [미정], Nav2, pick_server | 20 Hz | 인지(위치 추정) · 판단 |
| ④ 안전 | 최종 속도 제한·감속·정지 (팔 전류 감시는 pick_server 안) | velocity_smoother, collision_monitor (twist_mux는 선택) | 매 주기 | 제어 |
| ⑤ 하드웨어 | read → update → write | control_master(controller_manager) + OpenCR 2대 | 100 Hz | 제어 |

### 지킬 규칙

- **안전은 맨 뒤에 둔다.** 모든 속도 명령은 Nav2 복구 동작까지 포함해 velocity_smoother → collision_monitor를 거쳐 `/cmd_vel`이 된다. 접촉하면 실격이라 이 체인은 빼지 않는다.
- **안전 정지는 3단이다.** planning_master 입력 타임아웃 → control_master 명령 타임아웃 → 펌웨어 watchdog.
- **속도 명령은 체인 전체 TwistStamped.** 최근 ROS 2 배포판의 Nav2와 컨트롤러 기본값에 맞춘다.
- **TF 발행자는 하나씩.** 자세한 규칙은 아래 "통신 규칙"에 있다. 스월브 컨트롤러는 TF를 끄고 `/odom` 토픽만 낸다.
- **map → odom이 나오기 전에는 주행 목표를 보내지 않는다.**
- **판단 권한은 한 층에 하나.** 다시 정렬해 한 번 더 집기 같은 실행 세부는 pick_server가, 퍽을 건너뛸지 같은 임무 결정은 planning_master가 한다. 장애 판정은 health_monitor가 한다.
- **control_master(controller_manager)는 하나.** hardware component는 OpenCR별로 2개(팔, 스월브)를 올린다. IMU는 OpenCR 보드 내장 IMU를 쓰고, 어느 보드의 IMU인지는 **[미정]** 이다.
- **파트 안에서는 기능별로 노드를 나누고, 파트 사이 경계는 유지한다.** 영상을 주고받는 노드는 한 컨테이너(perception_master)에 컴포넌트로 묶어 실행한다. 다른 파트에는 정해진 토픽만 보인다.

### 토픽 이름 규칙

- 사람이나 밖에서 들어오는 명령은 `/cmd/...`. 보내고 끝이다(예: `/cmd/e_stop`, `/cmd/operation_mode`).
- 상태는 `/state/...`이고, 발행은 planning_master 하나만 한다. 바꾸고 싶으면 `/cmd/...`를 보낸다.
- 인지 결과는 `/perception/...`.
- 응답이 꼭 필요한 요청은 서비스, 오래 걸리는 동작은 액션으로 한다.

## 임무 흐름과 퍽 지도

<Callout type="warn" title="규칙 확정 전 가정">
  대회 세부 규칙이 아직 확정되지 않았다. 아래 임무 흐름(순회 → 운반)과 경광등·AprilTag·바코드 관련 내용은 규칙이 정해지면 바뀔 수 있다.
</Callout>

미로 지도는 주어지고 퍽과 신호등 위치만 바뀐다고 본다. 그래서 1단계에서 미로를 한 바퀴 돌며 퍽 지도를 만들고, 2단계에서 색깔별로 옮긴다.

1. **순회**: 판단이 정한 경유점을 따라 미로를 한 바퀴 돈다. 모든 선반이 전면 카메라 시야에 한 번 이상 들어오도록 경유점과 방향을 잡는다.
2. **기록**: puck_map이 퍽과 신호등 위치를 map 좌표로 누적한다.
3. **운반**: planning_master가 색깔별로 옮길 퍽과 순서를 정한다 → 저장된 위치로 이동 → 가까이서 재측정 → 그리퍼 카메라 정렬 → 집기 → 목적지에 내려놓기 → 해당 퍽을 PICKED로 변경 요청.

| 단계 | 담당 | 하는 일 |
| --- | --- | --- |
| 순회 경로 | 판단 | 경유점 계획과 주행 |
| 위치 추정 | 인지 (localization, 방식 [미정]) | 주어진 지도 기준 로봇 위치 추정. 지도는 만들지 않음 |
| 퍽 검출 | 인지 (detector) | 프레임마다 색 · 모양 · 자세 · 위치 측정, 선반 평면 투영 |
| 퍽 지도 | 인지 (puck_map) | 같은 퍽을 하나로 합치고, 고유 ID와 상태 관리 |
| 운반 계획 | 판단 (planning_master) | 색깔별 대상 퍽, 목적지, 순서 결정 |
| 집기 직전 정렬 | 인지 (hand_align, 그리퍼 카메라) | 정확한 위치와 yaw 보정 |

### 퍽 지도를 만드는 규칙

- **선반 평면 투영 (detector)**: 박스 아래쪽 가운데를 선반 윗면(z = 0.08 m) 평면에 투영해 base_link 기준 위치를 `/perception/pucks`로 낸다.
- **map에 누적 (puck_map)**: `/perception/pucks`를 영상이 찍힌 시각의 TF로 map 좌표로 바꿔 누적한다. 최신 TF를 쓰면 주행 중 위치가 밀린다.
- **합치기**: 기존 퍽과 거리가 합치는 범위 안이면 같은 퍽으로 본다. 범위는 관측 거리에 따라 키운다(가까우면 약 5 cm, 멀면 약 15 cm). 모양은 합치는 조건에 넣지 않는다. 누운 원통과 누운 직육면체를 헷갈리면 같은 퍽이 두 개로 등록되기 때문이다.
- **위치 갱신**: 가중 평균으로 갱신한다. 가중치는 $1/d^2$로, 가까이서 본 관측을 더 믿는다.
- **속성 결정**: 색 · 모양 · 자세 모두 관측할 때마다 투표해서 가장 많이 나온 값으로 정한다.
- **확정**: 0.5초 이상에 걸쳐 N번(초안 3번) 관측돼야 CONFIRMED가 된다. 30 fps에서 3프레임은 0.1초라 순간 오검출도 통과하기 때문이다.
- **신호등**: 같은 방식으로 위치를 map에 기록해서, 판단이 경로에 쓸 수 있게 한다(규칙 확정 전 가정).

### 인지 노드 파라미터 (값은 초안, 테스트로 조정)

| 노드 | 파라미터 | 초안 값 |
| --- | --- | --- |
| detector | `model_path`, `conf_threshold` | `best.engine`, 0.5 |
| detector | `detector_backend` (직접 추론 / Detection2DArray 구독) | `ultralytics` (라이선스 [미정]) |
| detector (선반 평면 투영) | `shelf_height` | 0.08 m |
| puck_map | `merge_radius_near`, `merge_radius_far` | 0.05 m, 0.15 m |
| puck_map | `confirm_min_obs`, `confirm_min_duration_s` | 3, 0.5 s |
| puck_map | `lost_timeout_s` (가까이 갔는데 안 보이면 LOST) | 3.0 s |
| puck_map | `map_frame` | map |
| hand_align | `hand_active_phases` | TRANSPORT |

카메라 기울기는 파라미터가 아니라 URDF(camera_link의 pitch) 한 곳에만 둔다. 투영, 퍽 지도, costmap, 스캔 변환이 모두 TF를 거치므로,
각도가 바뀌면 URDF 한 줄과 캘리브레이션만 다시 하면 된다.

<Callout type="key" title="(나) 안의 위치 보정">
  휠 오도메트리와 IMU를 합친 EKF도 시간이 지나면 위치가 틀어진다. 그래서 저장된 위치는 접근용으로만 쓰고, 집기 전에 반드시 다시 측정한다.
  드리프트가 크면 전면 점구름을 `pointcloud_to_laserscan`(target_frame: base_link, 바닥 위 약 3-40 cm)으로 스캔으로 바꿔 AMCL로 지도에 맞춘다.
  `depthimage_to_laserscan`은 카메라가 정확히 수평이라고 보고 영상 가운데 줄을 쓰기 때문에, 조금만 숙여도 바닥을 벽으로 잡아 쓰지 않는다.
</Callout>

### 실패 처리

실행 세부는 아래 계층이 먼저, 임무 결정은 planning_master가 한다.

| 상황 | 먼저 | 그래도 안 되면 |
| --- | --- | --- |
| 집기 실패 (그리퍼가 완전히 닫힘 = 빈손) | pick_server가 그리퍼 카메라로 다시 정렬해 1회 재시도 | pick_puck FAILED → planning_master가 다른 방향에서 1회 재계획 → 같은 단계 2회 연속 실패면 퍽을 LOST로 바꾸고 다음 퍽 |
| 이동 실패 (경로가 막힘) | Nav2가 복구 동작(Spin · Wait). 뒤를 못 보니 BackUp은 빼거나 0.1 m 이하 | ABORTED → planning_master가 다른 접근 위치로 1회 → 또 실패면 다음 퍽을 먼저 |
| 팔 접촉 감지 | pick_server가 전류가 기준을 0.1초 넘게 넘으면 궤적 취소 | pick_puck 결과 REASON_CONTACT → 집기 실패와 같은 규칙 |
| 비상 정지 | `/cmd/e_stop` → planning_master가 Nav2 목표와 pick_puck을 취소하고 `/state/emergency` 발행 | 해제되면 현재 단계부터 다시 |

<Callout type="warn" title="초안">

## 통신 규칙

받는 쪽이 '안 보임'과 '노드 고장'을 구분할 수 있도록, 인지 토픽은 결과가 없어도 항상 발행한다.

| 토픽 | 발행 주기 | 결과가 없을 때 | QoS |
| --- | --- | --- | --- |
| 카메라 영상 | 약 15-30 Hz | | SensorData (best effort) |
| `/perception/puck_map` | 목록이 바뀔 때 + 주기적(약 1 Hz) | 빈 배열 | reliable, depth 1, transient local |
| `/perception/tower_light` | 프레임마다, 최근 N프레임 기준 | `detected: false` | reliable, depth 1, transient local |
| `/perception/hand_target` | 프레임마다 | `detected: false` | reliable, depth 1 |

- 받는 쪽은 보내는 쪽 QoS에 맞춰야 한다. 맞지 않으면 에러 없이 메시지가 안 온다.
- 받는 쪽은 `header.stamp`를 보고, 예를 들어 0.5초 넘게 새 메시지가 없으면 멈추는 처리를 넣는다.
- 콜백에서는 값만 저장하고, 판단은 타이머에서 최신 값을 보고 내린다.

### TF 발행자와 안전 정지

- **odom → base_link**: localization(인지) 하나만 낸다.
- **map → odom**: (나) 안이면 출발 자세 고정값 또는 AMCL, (가) 안이면 미정.
- **안전 정지 3단**: planning_master 입력 타임아웃 → control_master 명령 타임아웃 → 펌웨어 watchdog.

### 좌표계

- map = 주어진 경기장 지도. 출발 자세를 초기 위치로 넣어 map → odom을 맞춘다.
- base_link = 차체 중심, 바닥 높이. x는 앞, y는 왼쪽, 단위는 m와 rad (REP-103).
- 퍽 지도와 신호등 위치는 map 기준, 실시간 검출(`/perception/pucks`)은 base_link 기준.
- TF는 최신 값이 아니라 영상의 `header.stamp` 시각으로 조회한다.
- 팔 제어는 TF로 arm_base_link 기준으로 바꾼다. 장착 위치 숫자를 코드에 넣지 않는다(장착 위치 [미정]).
- 판단은 가까이 간 뒤 해당 퍽의 `position_std`가 기준(초안 1 cm)보다 작아지면 집기 명령을 내린다.

### yaw 범위 규칙

인지가 줄여서 보내고, 팔 제어는 받은 값을 바로 롤 각도로 쓴다.

| 퍽 상태 | 대칭 | 보낼 범위 |
| --- | --- | --- |
| 서 있는 원통 | 어느 방향이든 같음 | 0 고정 |
| 서 있는 직육면체 | 90°마다 | −45°에서 +45° |
| 누운 원통 · 직육면체 | 180°마다 | −90°에서 +90° |

공통 설정: 모든 노드는 같은 `ROS_DOMAIN_ID`와 같은 RMW 구현을 쓴다. 카메라 노드는 한 곳에서만 실행하고, 컨테이너를 나눌 때는 `--network host --ipc host`를 쓴다.

## 정할 것 · 확인할 것

### 팀원과 합의

- **위치 추정 방식**: (가) cuVSLAM + RealSense / (나) 주어진 지도 + 휠·IMU EKF(부족하면 AMCL 추가). (가)라면 odometry를 받는 쪽과 TF 발행자. Isaac ROS(cuVSLAM)는 이 결정 전까지 Jetson에 설치 보류
- **검출기 라이선스**: YOLOv8·ultralytics는 AGPL-3.0이다. 저장소 라이선스(현재 MIT)와 함께 결정
- **팔 장착 위치**: 상면 중앙 / 중심에서 40 mm 앞 (실물 로봇에서 확인 후 확정)
- **IMU**: 두 OpenCR 중 어느 보드의 내장 IMU를 쓸지
- **OpenCR 펌웨어 방식**: 각 OpenCR(팔·스월브)에 직접 작성 펌웨어를 올릴지, 통과 모드로 쓸지 (dynamixel_hardware_interface 사용 여부와 제어 작업량이 달라짐)
- **그리퍼 카메라 토픽 이름**: 그리퍼 RealSense(realsense2_camera 두 번째 인스턴스)의 토픽 이름
- **UC-684 사용 여부** (쓴다면 UVC 방식인지, IR 차단 필터가 있는지). usb_cam·v4l2_camera는 이 결정 전까지 설치 보류
- 색깔별 목적지 (색마다 정해진 선반인지, 다른 방식으로 알려주는지)
- 퍽 개수, 하나씩 옮기는지 적재통에 여러 개 싣는지
- 출발 위치가 고정인지 (map → odom 초기화)
- 신호등의 역할: 출발 신호인지, 경로 중간의 정지/통과 신호인지
- 동적 장애물이 무엇이고 얼마나 빠른지
- 순회 경유점: 모든 선반이 D435 시야에 들어오는지
- 퍽 지도 파라미터: 합치는 범위, 확정 관측 횟수
- 스월브 컨트롤러 구현: ros2_control 플러그인 직접 작성 / 기존 패키지
- 팔 동작: pick_server 자체 IK / MoveIt, PickPuck.action 확정
- twist_mux를 쓸지 (수동 조작 테스트용)
- 경광등을 D435로 볼지, 손 카메라를 들어 올려서 볼지
- AprilTag·바코드: 어느 카메라로 읽을지, 용도, 출력 토픽
- D435 emitter: 켜는 쪽 추천 (장애물 감지·depth 보정)
- 옆·뒤 감지: 회전 후 이동으로 제한 / 예비 RealSense
- D435 기울기 (일단 10°로 테스트, 값은 URDF에만)
- 손 카메라를 롤 관절 앞에 달지 뒤에 달지 (앞 추천)
- HandTarget 오차 단위, yaw 범위 규칙
- `ROS_DOMAIN_ID`, RMW 구현(현재 기본값 Fast DDS 유지), 컨테이너 구성

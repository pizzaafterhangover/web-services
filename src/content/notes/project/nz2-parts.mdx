## 개요

KANT PA1 LV2 프로젝트2 **팀NZ2**의 로봇은 선반 위 퍽(서 있음/누움)을 인식·파지해 적재통에 넣고 다른 선반으로 옮기는 모바일 매니퓰레이터다.
임무 세부(순회 → 운반 등)는 대회 규칙이 확정되기 전의 **[가정]** 이다.

이 페이지는 인지·판단·제어 파트가 주고받는 노드·토픽 구조다. 파트 사이의 약속은 정해진 토픽·서비스·액션으로만 정하고, 각 파트 안쪽 구조는 바뀌어도 다른 파트에 영향이 없게 한다.

### 기준 사양

| 항목 | 값 |
| --- | --- |
| 차체 | 400 × 400 mm, 윗면 높이 180 mm, 스월브 4모듈 |
| 팔 | OpenMANIPULATOR-X, 링크 약 +100 mm 연장, 그리퍼 롤 회전 가능. 장착 위치 **[미정]** (상면 중앙 / 중심에서 40 mm 앞, 실물 확인 후 확정) |
| 카메라 | RealSense D435 2대. 전면(높이 180 mm, 틸트 10°, 네임스페이스 `/front`), 그리퍼(집게 상부, 네임스페이스 `/gripper`) |
| 연산 | Jetson Orin Nano Developer Kit. L4T R39.2.1, Ubuntu 24.04.5 LTS, ROS 2 Lyrical, Isaac ROS 5.0(cuVSLAM), Nav2 |
| 모터 제어 | OpenCR 2대. #1 스월브 ID 1-8(구동 1-4, 조향 5-8, XM430-W210), #2 팔 ID 11-16(팔 11-14 XM430-W350, 그리퍼 15, 손목 롤 16) |
| 위치 추정 | cuVSLAM + 휠 오도메트리(EKF 융합) + AMCL(depth → `/scan`). 휠 오도메트리는 4바퀴 모두 써서 FK로 계산 |
| 사용 안 함 | 라이다, IMU(**[검토 중]** cuVSLAM 트래킹을 잃으면 백업이 없어 재검토) |
| 작업 대상 | 퍽: 직육면체 30 × 30 × 60 mm, 원통(치수 실물 확인). 빨강·초록·파랑. 서 있음/누움. 선반(80 mm) 위에서 적재통으로 |

## 계층과 원칙

차트는 노드를 데이터가 흐르는 순서대로 8개 레인에 놓는다.

| 레인 | 노드 | 파트 |
| --- | --- | --- |
| Hardware (Sensors) | RealSense D435 ×2, 비상정지 스위치 | 하드웨어 |
| Drivers | realsense2_camera(`/front`, `/gripper`) | 인지 |
| Perception · Estimation | isaac_ros_cuvslam, ekf_node, depthimage_to_laserscan, map_server, amcl, slam_toolbox(매핑 시), obstacle_detector, yolo_detector, traffic_light_filter, apriltag_detector, barcode_reader, shelf_detector, puck_localizer, robot_state_publisher, perception_master | 인지 (robot_state_publisher는 공용) |
| Decision | mission_fsm | 판단 |
| Planning | planning_master, planner_server, approach_planner, grasp_planner, arm_ik_planner, bin_manager, traffic_behavior | 판단 |
| Control | path_tracker, dock_controller, arm_trajectory_executor, gripper_controller, control_master, velocity_smoother, collision_monitor, swerve_kinematics | 제어 |
| Low-level Control | swerve_bridge → OpenCR #1, arm_bridge → OpenCR #2 | 제어 · 펌웨어 |
| Hardware (Actuators) | 구동·조향 XM430-W210 ×4씩, 팔 XM430-W350 ×4, 그리퍼 15 · 롤 16, 12 V 모터 전원 릴레이 | 하드웨어 |

### 주요 설계 결정

- **스월브 역기구학은 Jetson에서** 계산한다(swerve_kinematics). OpenCR은 전류·속도 제한과 200 ms watchdog만 맡고, 상위 명령을 통과시킨다.
- **YOLO로 퍽(모양·자세)과 신호등을 검출**하고, 퍽 색은 bbox 안의 HSV로 판정한다 **[가정]**.
- **하위 플래너가 결과 토픽을 제어로 직접 발행**한다. planning_master는 서비스·액션 요청과 `/planning/drive_mode`를 맡는다.
- **신호등은 traffic_behavior가 `/perception/traffic_light`를 직접 구독**한다.
- **안전 3중**: control_master(타임아웃 200 ms · E-stop) → OpenCR 펌웨어 watchdog(200 ms) → E-stop 릴레이로 12 V 모터 전원 차단(하드웨어).
- **TF 발행자는 하나씩**: odom → base_link는 ekf_node만, map → odom은 amcl만 낸다.

## 임무 흐름

<Callout type="warn" title="규칙 확정 전 가정">
  대회 세부 규칙이 아직 확정되지 않았다. 아래 흐름과 적재통 위치, 신호등 위치·형태, AprilTag 실제 유무는 **[가정]** 이다.
</Callout>

1. **매핑(경기장 매핑 시간)**: slam_toolbox가 `/scan`으로 지도를 만들고 map_saver로 `map.pgm`·`map.yaml`을 저장한다. 경기 중에는 map_server가 이 지도를 읽는다.
2. **주행**: mission_fsm이 `/planning/execute_task` 액션으로 작업을 맡기면, planning_master가 planner_server에 경로를 요청하고 path_tracker가 따라간다. 신호등이 RED/YELLOW면 traffic_behavior가 HOLD를 건다.
3. **선반 접근**: shelf_detector가 AprilTag로 선반 pose를 구하고, approach_planner가 선반 앞 정렬 pose를 정해 dock_controller가 정밀 접근(0.05 m/s 이하)한다.
4. **집기**: puck_localizer가 YOLO bbox와 그리퍼 depth로 퍽 3D pose를 구한다. 퍽 위치는 0.25 m 이상 떨어진 pre-grasp 자세에서 측정한다 **[가정]**. grasp_planner(서 있음: 위 / 누움: 측면 + 롤) → arm_ik_planner(5축 해석적 IK · 간섭 검사) → arm_trajectory_executor 순서로 실행한다.
5. **적재**: bin_manager가 적재통 슬롯을 정하고 arm_ik_planner가 슬롯 자세로 팔을 옮긴다.

<Callout type="warn" title="[검토 중] 퍽 3D 매핑 경로">
  전면 depth가 퍽 위치 추정에 연결되어 있지 않고(puck_localizer는 그리퍼 depth만 받음), 순회 중 퍽 위치를 어떻게 지도에 쌓을지 정해지지 않았다. 집계는 perception_master가 맡는다.
</Callout>

<Callout type="warn" title="[개정 필요] 실패 처리">
  이전 설계(pick_server·pick_puck 기준)의 실패 처리 규칙은 새 노드 구조에 맞게 다시 정해야 한다. 비상 정지는 위의 "안전 3중"을 따른다.
</Callout>

## 통신 규칙

- 받는 쪽이 '안 보임'과 '노드 고장'을 구분할 수 있도록, 인지 토픽은 결과가 없어도 항상 발행한다.
- 받는 쪽은 보내는 쪽 QoS에 맞춰야 한다. 맞지 않으면 에러 없이 메시지가 안 온다. 토픽별 QoS 표는 새 토픽 기준으로 **[개정 필요]**.
- 받는 쪽은 `header.stamp`를 보고, 예를 들어 0.5초 넘게 새 메시지가 없으면 멈추는 처리를 넣는다.
- 콜백에서는 값만 저장하고, 판단은 타이머에서 최신 값을 보고 내린다.
- 카메라 영상이 약 130 MB/s라 composable node와 intra-process 통신으로 복사 비용을 줄인다.

### TF 발행자와 안전 정지

- **odom → base_link**: ekf_node 하나만 낸다.
- **map → odom**: amcl 하나만 낸다.
- **base_link → camera_link, gripper_cam**: robot_state_publisher가 URDF와 관절 상태로 낸다.
- **안전 3중**: control_master(타임아웃 200 ms · E-stop) → OpenCR 펌웨어 watchdog(200 ms) → E-stop 릴레이로 12 V 모터 전원 차단(하드웨어).

### 좌표계

- base_link = 차체 중심, 바닥 높이. x는 앞, y는 왼쪽, 단위는 m와 rad (REP-103).
- TF는 최신 값이 아니라 영상의 `header.stamp` 시각으로 조회한다.
- 팔 제어는 TF로 arm_base_link 기준으로 바꾼다. 장착 위치 숫자를 코드에 넣지 않는다(장착 위치 [미정]).
- 측면·후방 사각 때문에 costmap inflation을 0.33 m 이상(외접원 283 mm + 여유 50 mm)으로 둔다 **[검토 중]**.

### yaw 범위 규칙 [검토 중]

이전 설계의 규칙이다. grasp_planner(서 있음: 위 / 누움: 측면 + 롤) 기준으로 다시 확인한다.

| 퍽 상태 | 대칭 | 보낼 범위 |
| --- | --- | --- |
| 서 있는 원통 | 어느 방향이든 같음 | 0 고정 |
| 서 있는 직육면체 | 90°마다 | −45°에서 +45° |
| 누운 원통 · 직육면체 | 180°마다 | −90°에서 +90° |

공통 설정: 모든 노드는 같은 `ROS_DOMAIN_ID`와 같은 RMW 구현을 쓴다. 카메라 노드는 한 곳에서만 실행하고, 컨테이너를 나눌 때는 `--network host --ipc host`를 쓴다.

## 정할 것 · 확인할 것

### 차트의 확인 필요 항목

- 적재통 위치(문제 발표 후), 신호등 위치·형태 **[가정]**
- YOLO 모델 크기·클래스 정의, 신호등을 YOLO로 할지 HSV로 할지
- 제어의 `_raw` 중계를 twist_mux + enable 방식으로 단순화할지
- Orin Nano에서 Isaac ROS 5.0(cuVSLAM, AprilTag, RealSense) 실제 동작 확인

### [검토 중] 위험 요소

- **depthimage_to_laserscan**: 전면 10° 틸트에서 바닥을 벽으로 오인식할 위험(미해결). `/scan`이 amcl과 collision_monitor에 함께 들어간다.
- **측면·후방 사각**: D435 수평 FOV 약 87°. 벽 접촉 실격 위험을 costmap inflation 0.33 m 이상으로 완화하나 미검증.
- **퍽 3D 매핑 경로**: 전면 depth가 퍽에 연결되지 않았고, 순회 중 매핑 방법이 미확정. 이전 설계의 퍽 지도 규칙(관측 거리별 합치기 범위, 1/d² 가중 평균, 속성 투표, 0.5 s 동안 3회 관측으로 확정)을 perception_master 집계에 쓸지도 함께 정한다.
- **IMU 미사용**: cuVSLAM 트래킹을 잃으면 백업이 없다. 재검토.
- **Orin Nano GPU 부하**(YOLO + cuVSLAM): nano급 모델 TensorRT FP16, 단계별 카메라 교대 추론으로 대응.
- **cuVSLAM과 IR 도트 패턴 간섭**: emitter OFF / 교차 모드 비교 테스트.
- **벽면 바코드 판독**: 벽과 0.33 m 이상 유지한 거리에서 판독 해상도 사전 테스트.

### [보류] 새 차트에 없는 이전 설계 항목

- health_monitor와 `/diagnostics` → 판단 구조 (새 차트의 `/diagnostics`는 perception_master → rqt·로그만)
- `/cmd/*`(사람 명령), `/state/*`(임무 상태 방송) 토픽
- 커스텀 메시지 정의 전체 **[개정 필요]**, 실패 처리 규칙 **[개정 필요]**

### 팀원과 합의

- **검출기 라이선스**: YOLOv8·ultralytics는 AGPL-3.0이다. 저장소 라이선스(현재 MIT)와 함께 결정
- **팔 장착 위치**: 상면 중앙 / 중심에서 40 mm 앞 (실물 로봇에서 확인 후 확정)
- **OpenCR 펌웨어**: 차트 기준 역할은 전류·속도 제한 + 200 ms watchdog, 상위 명령 통과. 비상정지 신호를 받는 GPIO가 어느 보드인지 미정
- **UC-684 사용 여부** (쓴다면 UVC 방식인지, IR 차단 필터가 있는지). usb_cam·v4l2_camera는 이 결정 전까지 설치 보류
- 색깔별 목적지 (색마다 정해진 선반인지, 다른 방식으로 알려주는지)
- 퍽 개수, 하나씩 옮기는지 적재통에 여러 개 싣는지
- 출발 위치가 고정인지 (amcl 초기 위치)
- 신호등의 역할: 출발 신호인지, 경로 중간의 정지/통과 신호인지
- 동적 장애물이 무엇이고 얼마나 빠른지
- D435 emitter: 켜는 쪽 추천 (장애물 감지·depth 보정)과 cuVSLAM 간섭 비교
- D435 기울기 (일단 10°로 테스트, 값은 URDF에만)
- `ROS_DOMAIN_ID`, RMW 구현(현재 기본값 Fast DDS 유지), 컨테이너 구성

### 하드웨어 · 규정 확인

- 대회 세부 규칙 확정 (임무 흐름, 신호등·AprilTag·바코드 관련 가정 확인)
- 선반 깊이 (과제 도면)
- OpenCR 2대(스월브 8 + 팔 6) 기준 전원과 12 V 릴레이 배선 확인
- Raspberry Pi 4 역할 (안 쓰면 제외)
- 적재통 위치와 배출 모터
